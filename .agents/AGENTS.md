# AI Agent Behavioral & Domain Rules (AGENTS.md)

이 문서는 AI 어시스턴트(Antigravity)가 본 대시보드 프로젝트 작업 시 **반드시 준수해야 하는 엄격한 가이드라인 및 도메인 규칙**을 정의합니다.

---

## 1. 🚨 도메인 & DB 파라미터 규칙 (Strict Domain Rules)

1. **`tc` 파라미터 정의**:
   - `tc`는 **"전체(통합 서비스)"** 데이터를 조회하기 위한 ClickHouse DB 파라미터 코드입니다.
   - **절대로 `tc`를 임의의 브랜드명(예: 타임캐시 등)으로 지어내거나 억측하여 해석하지 마십시오.**

2. **앱 서비스 코드 목록 (App Options)**:
   - `tc`: 전체 (통합 데이터)
   - `bitbunny`: 비트버니
   - `yafit`: 야핏무브
   - `harustory`: 하루스토리

---

## 2. 🛡️ AI 행동 규칙 (Behavioral Guardrails)

1. **환각(Hallucination) 및 지어내기 절대 금지**:
   - 코드베이스, ClickHouse DB 스키마, 사용자 지시 사항에 없는 비즈니스 용어나 브랜드명을 지어내거나 추측하여 응답/코드에 작성하는 행위를 엄격히 금지합니다.

2. **사전 검증 및 사이드 이펙트 방지 (Regression Prevention)**:
   - 한 부분을 수정할 때 기존에 정상 작동하던 다른 탭, 차트, 데이터 연산이 파괴되지 않도록 꼼꼼히 사전/사후 검증하십시오.

3. **결정적 연산 및 일관성 보장 (Deterministic Output)**:
   - 동일한 조회 조건(앱, 기간, 단위)에서는 언제 실행하더라도 100% 일치하는 정밀한 연산 결과가 도출되도록 작성하십시오.

4. **솔직하고 기술적인 사실 기반 소통**:
   - 문제 발생 시 모호한 변명이나 핑계를 대지 말고, 실제 로그와 코드/DB 원인에 근거하여 명확하고 겸손하게 기술적 사실만을 설명하십시오.

5. **호칭 규칙 (Addressing Rule)**:
   - 사용자를 칭하거나 호칭할 때 '사용자분'이 아닌 **'하경님'**으로 명확히 부르십시오.

## 3. ⚡ 대시보드 탭별 데이터 격리 및 쿼리 최적화 규칙 (Tab Data Isolation Rules)

1. **메인 탭간 독립적인 데이터 패칭 (Strict Active-Tab Scoped Fetching)**:
   - 유저 현황, 매출 현황 및 추후 신규 추가되는 모든 메인 탭은 완전히 독립적인 영역입니다.
   - 글로벌 필터(날짜/앱 등) 변경이나 탭 전환 시 **현재 활성화된(Active) 탭에 필요한 DB 쿼리만 선별적으로 조회**해야 하며, 비활성화된 다른 탭의 쿼리를 불필요하게 동시에 호출하는 행위를 엄격히 금지합니다.

## 4. 💰 서비스 포인트 & 손익 마진 연산 규칙 (Point & Profit Margin Business Rules)

1. **미션 지급 리워드 단위**:
   - 미션 지급 리워드는 원화(원)가 아닌 **포인트(P)** 단위입니다.
   - 1P ≠ 1원이므로 **미션 지급 리워드는 반드시 `P` 단위로 표기**해야 합니다. (예: `94,527 P`)

2. **재화 구조 및 순 영업 마진 수식**:
   - 미션으로 획득하는 P(포인트)는 **중간 재화**입니다.
   - 유저가 포인트를 실제 재화로 최종 전환/환전할 때 실질 원화(원) 비용(`totalExchangedPoints`)이 발생합니다.
   - **실제 리워드 환전 비용 (원)** = `totalExchangedPoints` (포인트 교환 / 환전액)
   - **순 영업 마진 (원)** = `전체 총 매출 (grossRevenue)` - `포인트 교환 / 환전액 (totalExchangedPoints)`
   - **미션 지급 리워드(P)를 원화 매출에서 직접 빼는 오연산을 절대로 범하지 마십시오.**
